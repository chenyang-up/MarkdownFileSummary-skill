# 摘要撰写规范（给 AI 的执行标准）

本技能的价值来自**逐篇精读后的语义提炼**。脚本只负责发现、读取、解析与排版，
不产出任何摘要文字。以下标准是硬性要求。

## 1. 三条铁律

1. **必须读全文。** 读入每个文件的完整正文后再动笔；不得只看标题、大纲或首段就下结论。
2. **禁止拼接冒充摘要。** 不得把原文段落、首段、句子列表直接搬进 `summary` 字段充数。
3. **禁止编造。** 只写原文支持的结论；原文没说的推论必须标注「推论：」。

> 若某文件确实无法读取或为空，在 `summary` 中写明原因，而不是留空。

## 2. 大文件怎么读

正文超过约 2000 行或 8 万字符时，分块阅读：

1. 先读标题大纲与首尾段，建立整体结构假设；
2. 逐块精读，边读边在草稿中记录要点（论点 / 数据 / 结论）；
3. 读完后合并草稿，去除重复，形成摘要。

## 3. 单篇摘要要写什么

长度参考：**正文的 5%–20%**，且不少于 `content.per_file.min_summary_chars`（默认 200 字）；
信息密度低的可短一些，但**必须覆盖**下列要素：

| 字段 | 要求 |
| --- | --- |
| `title` | 文档主题，而非文件名 |
| `one_liner` | 一句话说清「这篇讲了什么、结论是什么」 |
| `summary` | 多段详细摘要：主旨 → 结构与脉络 → 关键论证 → （如有）数据与结论 |
| `key_points` | 3–8 条核心要点，每条一个完整判断，避免只写名词 |
| `details` | 重要数据、时间、人名、术语定义、前提条件等易被忽略的事实 |
| `quotes` | 1–3 句最能代表原文的关键句，逐字摘录，可含简短上下文 |
| `conclusions` | 作者结论、影响、风险、待办 |
| `tags` | 1–4 个主题标签，便于跨文件聚类 |
| `importance` | `high` / `medium` / `low`，相对本批文档而言 |

写 `summary` 时的常见错误：

- 只做目录复述（「本文分为三部分……然后……最后……」）→ 需要写出每部分的**内容与判断**。
- 只堆砌细节没有主线 → 先给结论，再给支撑。
- 各篇摘要高度雷同 → 说明没有逐篇读，需要重做。

## 4. 全局综述要写什么

`global.overview` 是**跨文件的综合**，不是把各篇摘要贴在一起：

1. 这批文档在谈什么，整体结论是什么；
2. 文档之间的关系（递进 / 并列 / 相互矛盾）；
3. 共识与分歧，以及分歧的根因；
4. 阅读建议（想了解 X 先读哪篇）。

配合字段：

- `key_findings`：跨文件才能得出的结论；
- `themes`：把不同文档中同一主题的内容聚在一起，`sources` 列出出处；
- `conflicts`：互相矛盾、口径不一致或语焉不详之处；
- `actions`：明确的后续动作。

## 5. 交付前自检

- [ ] 每个输入文件都在 `files` 中有条目？
- [ ] 每条 `summary` 都是重新组织的语言，能在原文中找到依据？
- [ ] `key_points` 是否都在讲「结论」，而不只是「话题」？
- [ ] `global.overview` 是否提到了至少两篇文档之间的对照关系？
- [ ] 是否有为了凑字数而写的空话？有则删掉。

自检后运行：

```bash
python3 "$SKILL_DIR/scripts/main.py" validate --root <目录> \
  --manifest <临时目录>/manifest.json --summaries <临时目录>/summaries.json
```

`validate` 会报告缺失、过简与缺少要点的问题，全部通过后再 `assemble`。
（`$SKILL_DIR` = 技能根目录，即 `SKILL.md` 所在目录；不传 `--config` 时自动使用技能自带配置。）
