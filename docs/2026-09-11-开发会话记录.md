## 二、逐轮详录

### 第 1 轮：搭项目结构（v1）

**用户诉求**

创建一个能在多个 coding 工具使用的 skill，功能是读取指定目录下多个 Markdown 文件、生成一份汇总/总结性的新 Markdown 文件。要求规划完整项目结构，明确各组件（配置文件、主入口、解析模块、输出目录）的命名规范与目录层级，定义输入筛选规则、输出命名约定、内容组织形式，结构简洁清晰、便于跨工具移植。

**判断思路**

- 关键是「逻辑一份、入口多份」：`SKILL.md` 是跨工具的事实标准入口，各工具差异只放薄适配层，不复制业务逻辑。
- 技术选型上刻意做减法：只用 Python 标准库，连 YAML 都不引入（自研 YAML 子集解析器），这样在任何工具环境都能开箱即用。
- 把「文件发现 → 结构解析 → 内容组装」拆成三个独立脚本，便于单测和替换。

**执行动作**

新建 22 个文件：

```
SKILL.md                        # 规范入口（YAML frontmatter: name/description/license/metadata）
README.md                       # 人类可读说明（重写）
config/default.yaml             # 唯一配置中心
scripts/main.py                 # CLI 编排
scripts/config.py               # 配置加载（YAML 子集 + JSON，零依赖）
scripts/collect.py              # 输入发现与筛选
scripts/parse.py                # Markdown 结构解析
scripts/build.py                # 汇总文件组装
references/filter-rules.md      # 筛选规则细则
references/output-format.md     # 输出格式与命名约定
references/config-schema.md     # 配置字段说明
assets/templates/summary.md     # 输出骨架模板

examples/input/01-项目概述.md   # 示例输入 ×3

```

**实际踩到的坑**

argparse 的全局 `--config` 必须写在子命令**之前**，否则报
`unrecognized arguments`。修法：用 `argparse.ArgumentParser(add_help=False)` 造一个
`common` 父解析器，让每个子命令都 `parents=[common]`，这样 `--config` 可以写在子命令后面。

**验证**

```
discover → 3 个文件
assemble → examples/output/SUMMARY-example.md（2255 字符）
```

**当时定下的内容组织形式**

| 模式 | 内容 |
| --- | --- |
| `overview` | 全局概览 + 文件索引表 |
| `per-file` | 每文件一节：元信息 + 摘要 + 关键点 |
| `merged` | 按顺序拼接正文 |
| `full`（当时默认） | 三部分全要 |

### 第 2 轮：改成 AI 语义汇总（v2）

**用户诉求**

强调这**不是**简单的统计拼接，必须由 AI 对每篇内容进行读取、针对重点汇总，内容要详细。

**判断思路**

这是本项目最重要的一次定位修正。核心是**把分工写死**：

- 脚本负责发现、读取、解析、排版、**校验**，**不生成任何摘要文字**；
- AI 负责逐篇精读全文后撰写摘要与跨文件综述。

为了让「偷懒拼接」在成品里一眼可见，做了两个防御设计：

1. 摘要字段为空时，输出显式写「待 AI 精读原文后撰写」，**绝不用正文首段冒充摘要**；
2. 新增 `validate` 子命令卡质量（缺摘要 / 摘要过简 / 缺核心要点 / 缺全局综述），不通过就 `exit 1`，必须先补写。

**执行动作**

- `summaries.json` schema 扩展：

  ```json
  {
    "global": {"overview": "", "key_findings": [], "themes": [], "conflicts": [], "actions": []},
    "files": {
      "<相对路径>": {
        "title": "", "one_liner": "", "summary": "", "key_points": [],
        "details": [], "quotes": [], "conclusions": [], "tags": [], "importance": "high"
      }
    }
  }
  ```

- `content.mode` 改为 `digest`（默认，推荐）/ `full`（加合并正文附录）/ `overview` / `merged`（纯拼接，标注不推荐）；合并正文从核心节降级为附录。
- 输出结构改为五节：全局综述 → 主题脉络 → 文件索引 → 分文件详细摘要 →（full 时）合并正文附录。
- 新增 `references/summarization-guide.md`，写死三条铁律：**必须读全文 / 禁止把原文段落搬进摘要 / 禁止编造**；并给出大文件分块读法、每字段撰写标准、交付前自检清单。
- `config/default.yaml` 升到 `version: 2`；`per_file` 增加 `include_one_liner / include_details / include_quotes / include_conclusions` 与 `min_summary_chars`（默认 200）；新增 `global` / `index` 分节开关。
- `build.py` 重写，`validate()` 返回问题列表。

**验证**

```
validate（空摘要负例）→ 报出 4 个问题：缺少摘要 ×3 + 缺少全局综述，exit 1
assemble              → 4968 字符（v1 拼接版约 2255 字符）
```

### 第 3 轮：加输入上限

**用户诉求**

1. 单文件不得超过 30MB，通过配置字段限制；
2. 选择的文件数量不得超过 30 个。

**判断思路**

- 上限**不报错中断**，而是跳过 + 留痕（写入 `manifest.json.skipped`）+ 命令行提示。这样 AI 知道哪些文件没被汇总，交付时必须告知用户，而不是静默丢文件。
- 性能上先 `stat()` 判体积再读内容，避免为超限大文件付出 IO 代价。

**执行动作**

- `input.max_file_bytes: 31457280`（30 MiB）、`input.max_files: 200 → 30`。
- `collect.discover()` 返回值由二值改为三值 `(root_path, files, skipped)`；新增 `summarize_skipped()` 生成人类可读提示。
- 跳过原因三种：`too_small` / `too_large` / `over_max_files`。
- `main.py` 新增 `_discover(cfg, root, quiet)` 统一解包与提示；`discover` 回显当前上限；manifest 增加 `skipped_count` 与 `skipped`。
- 同步 `references/filter-rules.md`（新增判定顺序、截断时机、reason 表）、`config-schema.md`、`SKILL.md`、`README.md`。

**验证**

```
max_file_bytes=200 → 85B 文件全部 skipped(too_large)
默认 30MB          → 33.1MB 的 big.md 被 skipped(too_large)
max_files=3 / 5 篇 → 纳入 3 篇，跳过 2 篇(over_max_files)
回归               → examples 3 篇全流程通过
```

**关键语义**：`max_files` 的截断发生在**排序之后**，保留哪几个由 `input.sort` 决定（默认 `path_asc`；改 `mtime_desc` 则优先保留最新的）。

### 第 4 轮：默认输出到桌面

**用户诉求**

默认输出到桌面；用户指定了输出位置则以指定为准。

**判断思路**

「默认桌面」与「相对路径可承载到项目内」两个诉求要同时满足，所以解析规则设计成：

- `~` 开头或绝对路径 → 按原样使用；
- 相对路径 → 相对 `input.root` 解析。

优先级：`--out`（完整文件路径）> `--out-dir`（目录）> `output.dir`。

**执行动作**

- `output.dir: "./_summary"` → `"~/Desktop"`（`config/default.yaml` 与 `config.py` 的 `DEFAULTS` 同步）。
- 新增 `build.resolve_output_dir(cfg, root_path)`，`compute_output_path` 改为调用它。
- `main.py` 的 `--out` / `--out-dir` help 文案补上优先级说明。
- 同步 `output-format.md`、`config-schema.md`、`SKILL.md`、`README.md`、两个 adapters。

**验证**

```
默认（用假 HOME=/tmp/fakehome 验证，避免污染真实桌面）
  → /tmp/fakehome/Desktop/SUMMARY-input-20260911-112058.md
```

### 第 5 轮：怎么加到 WorkBuddy 测试（只出方案）

**用户诉求**

先给方案，不要修改或其他处理。

**只读排查结论**

```
~/.workbuddy/skills/
├── kaoyan-english-skill__skillhub/
├── kunlun-prompt-eng__skillhub/     ← SKILL.md + references/ + _meta.json + _skillhub_meta.json
└── _bm_skillid_migration.json
```

- 项目级目录 `{workspace}/.workbuddy/skills/` 当时**不存在**；`_meta.json` / `_skillhub_meta.json` 是市场安装时生成的，本地自建 skill 不需要自己造。
- **风险 1（相对路径）**：文档写的是 `python3 scripts/main.py --config config/default.yaml`，两处都相对 cwd；skill 加载后 agent 的 cwd 通常是工作区而非技能目录，照抄必失败。
- **风险 2（frontmatter 形态）**：市场 skill 用顶层 `version` / `displayName` / `tags` / `billing`；本项目用的是嵌套 `metadata.version`，能否被识别需实测。

**给出两条路线**

- 路线 A：不安装，直接读 `SKILL.md` 按流程用**绝对路径**跑一次——验脚本正确性，不验加载与触发。
- 路线 B：正式安装（用户级 `~/.workbuddy/skills/` 或另建测试工作区），先试 `ln -s`（改代码即时生效），不被识别则退回 `cp -R`；重载后触发验证。
- 另提醒：安装新 skill 前应过一遍安全审计；不要把技能装进本仓库自己的 `.workbuddy/skills/`（自引用）。

### 第 6 轮：一般 skill 项目怎么测

**回答要点（五层模型）**

| 层 | 内容 | 特性 |
| --- | --- | --- |
| L0 | 结构与静态校验：frontmatter 必需字段、目录完整、路径引用存在、脚本语法 | 秒级，可 CI |
| L1 | 脚本单元测试：纯函数 + 边界（空目录、超限、重名、非 UTF-8、无 frontmatter） | 秒级，可 CI |
| L2 | 端到端冒烟：子进程跑完整 CLI，断言产物与**退出码** | 分钟级，可 CI |
| L3 | 加载与触发测试：装入 skills 目录重载，测命中**与误触发** | 人工，改 description 必测 |
| L4 | 行为质量评估：固定输入 + rubric 打分 | 概率性，抽样复评 |

**通用实践**

- fixture 隔离到临时目录（本技能默认输出到桌面，测试必须 `--out-dir` 到 tmp）；
- 冻结时间戳与文件名模板，让产物可 diff、可断言；
- 契约测试锁 CLI（子命令名、参数、退出码都是对外承诺）；
- 多 Python 版本矩阵（声明支持 3.9+ 就该在 3.9 与最新版都跑）；
- 安装可回滚（软链优于覆盖）；
- L4 不要断言具体文本，只断言结构（是否全覆盖、是否出现「待补充」、是否含跨文件对照）。

**当时建议的 tests/ 结构（尚未创建）**

```
├── test_collect.py     # glob、排除、30MB/30 个上限、排序截断
```

### 第 7 轮：修相对路径，准备用户级测试

**用户诉求**

进行用户级测试；针对相对路径问题怎么调整；**之后所有修改都要展示给他查看**。

**判断思路**

不能用硬编码绝对路径（那条路径是开发仓库，装到 `skills/` 后就失效），正确做法是**让技能自己知道自己在哪**：

- 引入 `$SKILL_DIR` = `SKILL.md` 所在目录（技能根目录）；
- 文档与适配层里的命令统一写 `python3 "$SKILL_DIR/scripts/main.py"`；
- `--config` 改为可选：省略时按**脚本位置**解析技能自带的配置；
- `--root` 与中间产物路径仍相对 cwd——这是刻意的：用户想汇总哪个目录就在哪执行。

**执行动作（8 个文件）**

1. `scripts/main.py`
   - 新增 `_SCRIPTS_DIR` / `SKILL_DIR` / `DEFAULT_CONFIG` 常量；
   - 新增 `_load_cfg(args)`，`args.config or str(DEFAULT_CONFIG)`，替换 4 处调用点；
   - `--config` 默认由字符串 `"config/default.yaml"` 改为 `None`；
   - **顺带修 bug**：`_dump()` 原来不创建父目录，`--out /tmp/x/manifest.json` 会 `FileNotFoundError`；已加 `mkdir(parents=True, exist_ok=True)`。
2. `SKILL.md`：新增「路径约定（重要）」小节；工作流 4 条命令改为 `$SKILL_DIR` 形式并去掉 `--config`；「关键约定」两条更新。
3. `README.md`：新增「安装到 WorkBuddy（用户级测试）」小节；快速开始改用 `SKILL_DIR=...` + 绝对路径；配置小节补「不传 `--config` 即用自带配置」。
4. `references/config-schema.md`：新增「配置文件位置」小节 + 调用示例。
5. `references/summarization-guide.md`：自检后的 `validate` 命令改为 `$SKILL_DIR` 形式（复查时发现的遗漏）。
6. `adapters/README.md`：新增「适配层不得硬编码技能安装路径，一律用 `$SKILL_DIR` 占位」约束。
7. `adapters/cursor/.cursor/rules/md-summary.mdc`：整体重写。
8. `adapters/codex/AGENTS.md`：整体重写。

**验证**

```
从 /tmp 用绝对路径调用，全程不带 --config：
  discover → 3 个文件
  extract  → 3 个文件
  validate → 校验通过
  assemble → /tmp/mdtest_out/SUMMARY-input-20260911-131922.md
对照：显式 --config 传绝对路径仍可用
残留检查：全局仅剩 SKILL.md 里那句故意保留的「反面示例」
```

**两点设计判断（已写入长期约定）**

- 不做硬编码绝对路径；`SKILL.md` 里 `metadata.entrypoints: - scripts/main.py` 保留不动——那是技能清单里的相对声明，语义正确。

## 四、关键约定（改动时不可违反）

1. **分工不可动摇**：脚本不生成任何摘要文字；AI 读全文写摘要与综述；摘要缺失时必须显式标注「待补充」。
2. **零第三方依赖**：仅 Python 3.9+ 标准库，配置用自研 YAML 子集解析。
3. **路径约定**：`$SKILL_DIR` = `SKILL.md` 所在目录；文档/适配层一律 `python3 "$SKILL_DIR/scripts/main.py"`；`--config` 省略时按脚本位置解析；**禁止硬编码本机绝对路径**。
4. **输入上限**：单文件 ≤ 30 MiB（`max_file_bytes`），单次 ≤ 30 个文件（`max_files`）；超限跳过并留痕，必须向用户说明被跳过的文件。
5. **输出位置**：默认 `~/Desktop`；优先级 `--out` > `--out-dir` > `output.dir`；交付时必须回报完整路径。
6. **validate 是闸门**：不合格返回 exit code 1，用于卡住质量不达标的产出。
7. **SKILL.md 是唯一规范入口**；`adapters/` 只做薄封装，不得复制业务逻辑、不得硬编码安装路径。

## 五、CLI 契约

```bash
SKILL_DIR=/path/to/MarkdownFileSummary-skill   # 例如 ~/.workbuddy/skills/markdown-file-summary

# 2. 读取全文与结构

  --manifest <临时目录>/manifest.json --summaries <临时目录>/summaries.json
```

## 十、第 9 轮：显式文件清单（会话进行中增补）

### 用户诉求（4 条）

1. **显式文件清单**：用户在工具里填写的多个文件地址，或通过工具添加的多个附件。两者都有时**都要读取**；若是上传的附件，汇总文件里的子文件链接地址要记录**本地上传地址**。
2. 只给了目录路径 → 只查目录中的所有文件。
3. 优先级：**显式文件清单 > 文件目录**。
4. 限制：只支持本地文件地址或本地上传地址，**http/https 的 OSS 地址不支持**。

### 歧义的读法（已实现为可切换）

- 需求 1 的「若都有」= **填写的地址 + 添加的附件两种来源都要读**（同一机制的两次输入，合并去重）。
- 需求 3 的「清单优先」= 清单与目录同时存在时**忽略目录**；`input.merge_files_and_root: true` 可改为合并。

### 顺带修掉的两个真实 bug

1. **`config.py` 的 `_coerce` 不支持 flow 序列**：`files: []` 被解析成字符串 `"[]"`，导致遍历出 `[` 和 `]` 两个假文件。同理 `include: ["**/*.md"]` 这种写法一直是坏的（glob 会变成一个带方括号的字符串）。已支持 `[]` / `[a, b]` / `["a", "b"]`，并按顶层逗号切分、忽略引号内逗号。
2. **`--out -` 时提示信息污染 stdout**：`已跳过 …` 打到了 stdout，破坏 JSON 管道。已引入 `_info()`，所有人读信息走 stderr，stdout 只留机器可读内容。
